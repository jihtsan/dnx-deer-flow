## Problem Statement

知识库中的知识图谱目前虽然已经能够展示 LightRAG 返回的全局实体和关系，但页面的信息结构与用户理解不一致。顶部入口展示的是具体热门实体，却使用了容易被理解为分类或分组的表达；LightRAG 已经提供的原始实体类别被前端压缩为少量通用类别，无法真实反映知识库中的类型构成。

用户进入图谱时还需要面对过度简化的节点详情、与实体详情混在一起的关系列表，以及可能命中当前画布之外实体的搜索结果。关系方向、描述、权重和来源没有在关系边上形成清晰的渐进式展示。图谱数据量达到数千节点或发生截断时，类别数量和搜索范围的统计口径也不够明确。

用户需要的是一个直接打开、忠实呈现 LightRAG 数据、能够承载最多 5,000 个逻辑节点的全局知识图谱。它应通过实体类别、搜索、节点详情和关系边交互帮助用户理解当前已加载图谱，而不是要求用户先选择中心实体，或把实时场站拓扑与文档知识图谱混为一谈。

## Solution

在知识库工作台中提供以 Canvas 为主要渲染面的 LightRAG 全局知识图谱。图谱默认展示当前 Loaded Graph 的所有实体、关系和不连通分量，最多承载 5,000 个逻辑节点，并明确展示截断状态。

图谱上方只保留一行“实体类别 Top 20”。类别直接来自 LightRAG 原始 `entity_type`，按当前已加载节点数量降序排列并显示数量。选择类别时突出该类别节点，其他节点和跨类别关系保留但降低视觉权重。空白类别归入“未分类”，Top 20 之外归入“其他”，颜色映射保持稳定且不作为唯一识别手段。

实体搜索限定在当前 Loaded Graph，保证每个结果都能在 Canvas 中定位。搜索优先于类别聚焦，选择结果后清除类别状态、定位实体、打开实体详情并突出一跳 Relationship Edge。

实体详情只展示被选实体本身的信息。Relationship Edge 在全局状态不常驻标签；选中实体后，一跳高亮边展示关系类型或关键词及 Relationship Weight，悬停或点击边时再显示关系描述和来源文件名。来源文件名一期只读展示，不提供文档跳转或预览。

图谱只在首次进入、过期后再次进入或用户手动刷新时重新获取数据。查看过程中不轮询，也不因窗口重新获得焦点而重排画布。一期只验收桌面端，移动端交互留作后续适配。

## User Stories

1. As a 知识库使用者, I want 进入知识图谱后直接看到全局图谱, so that 我不需要先理解或选择中心实体。
2. As a 知识库使用者, I want 图谱只展示 LightRAG 已索引文档产生的数据, so that 我不会把文档知识与实时场站拓扑混淆。
3. As a 知识库使用者, I want 同时看到不同文档形成的不连通图谱分量, so that 小型文档的知识不会被最大连通分量遮蔽。
4. As a 知识库使用者, I want 在图谱顶部看到实体类别 Top 20, so that 我能快速理解当前 Loaded Graph 的知识类型构成。
5. As a 知识库使用者, I want 每个实体类别同时显示实体数量, so that 我能比较不同类别的覆盖规模。
6. As a 知识库使用者, I want 实体类别按数量降序稳定排列, so that 重要类别优先出现且刷新后顺序可预期。
7. As a 知识库使用者, I want 实体类别使用 LightRAG 原始 `entity_type`, so that 页面不会用前端推断类别替换真实数据。
8. As a 知识库使用者, I want 空白类别显示为“未分类”, so that 数据抽取质量问题不会被静默隐藏。
9. As a 知识库使用者, I want Top 20 之外的类别归入“其他”, so that 顶部入口保持可扫描，同时节点仍保留原始类别。
10. As a 知识库使用者, I want 同一实体类别保持稳定颜色, so that 我在同一数据集上反复查看时能够形成一致认知。
11. As a 色觉差异用户, I want 类别状态同时通过文字、数量、描边和透明度表达, so that 我不依赖颜色也能理解当前选择。
12. As a 知识库使用者, I want 点击类别后突出对应节点而不删除其他节点, so that 我能聚焦类别并继续理解跨类别关系。
13. As a 知识库使用者, I want 一键恢复全部类别, so that 我可以快速返回全局总览。
14. As a 知识库使用者, I want 搜索当前已加载实体, so that 我能在数千节点中快速定位目标实体。
15. As a 知识库使用者, I want 每个搜索结果都能在画布中定位, so that 搜索选择不会表现为无响应。
16. As a 知识库使用者, I want 图谱截断时看到“仅搜索已加载节点”, so that 我不会把搜索无结果误解为整个 workspace 中不存在该实体。
17. As a 知识库使用者, I want 搜索选择自动清除类别聚焦, so that 搜索实体不会被先前类别状态弱化。
18. As a 知识库使用者, I want 选择搜索结果后看到实体详情和一跳关系, so that 我能立即理解实体及其直接上下文。
19. As a 知识库使用者, I want 点击任意节点后只查看该实体本身的详情, so that 详情面板不会被重复的关系列表占满。
20. As a 知识库使用者, I want 实体详情展示名称、原始类别、描述、来源文件名和当前图谱关联数, so that 我能理解实体含义及其数据来源。
21. As a 知识库使用者, I want 缺失实体描述时看到明确空状态, so that 页面不会生成或暗示不存在的内容。
22. As a 知识库使用者, I want “当前图谱关联数”明确限定统计范围, so that 图谱截断时我不会把它理解为完整 LightRAG 关联总数。
23. As a 知识库使用者, I want 点击实体后突出一跳 Relationship Edge 和直接关联实体, so that 我能看清目标实体的直接关系路径。
24. As a 知识库使用者, I want 高亮边展示方向、关系类型或关键词以及 Relationship Weight, so that 我能理解关系的语义、方向和强度。
25. As a 知识库使用者, I want Relationship Weight 明确标注为关系权重, so that 我不会把它误解为置信度、概率或准确率。
26. As a 知识库使用者, I want 悬停或点击高亮边时查看关系描述和来源文件名, so that 详细信息按需出现而不会挤满整个画布。
27. As a 知识库使用者, I want 全局状态不常驻显示全部边标签, so that 大型图谱仍然可读。
28. As a 知识库使用者, I want 来源文件名以只读文本展示, so that 页面不会暗示一期尚未支持的文档跳转或预览能力。
29. As a 知识库使用者, I want 图谱截断时看到明确提示和已加载节点统计口径, so that 我不会把 Loaded Graph 当作完整 workspace 图谱。
30. As a 知识库使用者, I want 查看图谱时节点位置不会被后台轮询突然重排, so that 我可以持续完成当前探索任务。
31. As a 知识库使用者, I want 手动刷新图谱, so that 我可以在需要时获取最新 LightRAG 数据。
32. As a 知识库使用者, I want 文档索引或删除后图谱被标记为过期, so that 下次进入图谱时能看到更新后的数据。
33. As a 知识库使用者, I want LightRAG 离线、空图和截断图具有不同状态, so that 我能区分服务故障、没有知识和只加载部分知识。
34. As a 桌面端知识库使用者, I want 在 1,024px 及以上视口稳定使用图谱, so that 一期核心工作台体验具有明确支持边界。
35. As a 大型知识库使用者, I want 图谱支持最多 5,000 个逻辑节点且保持平移、缩放和点击可用, so that 我能浏览真实规模的知识集合。
36. As a 维护者, I want 图谱不为每个节点创建 DOM 元素, so that 节点规模增长不会引入逐节点布局和事件开销。
37. As a 维护者, I want 图谱标签随缩放级别控制密度, so that 节点数量不会直接转化为不可读的标签数量。
38. As a 维护者, I want 同一图谱输入产生稳定类别顺序、颜色和布局, so that 自动化测试和用户视觉定位都可重复。
39. As a 维护者, I want 页面只消费归一化的 LightRAG 字段, so that 前端不会依赖上游私有诊断或敏感路径。
40. As a 产品负责人, I want 一期范围明确排除移动端、文档预览和场站控制, so that 实现可以集中在桌面端 LightRAG 图谱的正确性和可用性。

## Implementation Decisions

- 一期继续使用现有 Knowledge Graph 全局读取契约，不新增数据库表或持久化 schema。
- Loaded Graph 默认最多包含 5,000 个逻辑节点，并保留后端返回的全部不连通分量。节点、边、总标签数、分量数和截断状态继续由归一化全局图谱响应提供。
- 图谱默认是全局总览，不提供必选中心实体控件，也不创建独立的局部图谱数据集。
- 顶部现有热门实体快捷入口由“实体类别 Top 20”替换；一期不同时展示热门实体入口。
- 实体类别由当前 Loaded Graph 的节点 `entity_type` 聚合得出，不发起全 workspace 类别统计请求。
- 类别按已加载实体数量降序排列；同数量时采用稳定的类别名称顺序。类别入口显示名称和数量。
- 空白或缺失的 `entity_type` 归入“未分类”，使用中性色并参与 Top 20 排名。
- Top 20 之外的实体归入“其他”显示类别，但节点详情保留 LightRAG 原始类别。
- Top 20 类别使用基于原始类别值的稳定颜色映射。类别选择同时通过文字、数量、描边和透明度表达，不以颜色作为唯一状态信号。
- 类别聚焦只改变视觉权重：目标类别节点突出，其他节点和跨类别 Relationship Edge 保留并弱化。
- 实体搜索只覆盖当前 Loaded Graph。实现可以在已加载节点上建立轻量搜索索引，不继续向用户返回无法在当前 Canvas 定位的 workspace 实体。
- 图谱截断时，类别区域显示“基于已加载的 {node_count} 个节点统计”，搜索区域显示“仅搜索已加载节点”。
- 搜索选择优先于类别聚焦：清除类别状态、定位实体、突出一跳关系并打开详情。关闭详情后保持“全部类别”。
- 实体详情只展示实体名称、LightRAG 原始类别、实体描述、安全化来源文件名和当前图谱关联数。
- 实体详情不展示关联实体排序或完整关系列表。关系语义归属于 Canvas 上的 Relationship Edge。
- 选中实体后突出一跳 Relationship Edge 和直接关联实体。全局状态不常驻显示全部边标签。
- 一跳高亮边显示关系方向、关系类型或关键词及 Relationship Weight；边悬停或点击浮层显示关系描述和安全化来源文件名。
- Relationship Weight 使用 LightRAG 原始数值并明确标注，不转换为置信度、概率或准确率。
- 来源文件名一期只读展示，不增加本地文档标识映射，不提供文档详情或预览跳转。
- 图谱继续采用 Canvas 渲染，不创建逐节点 DOM。布局和邻接计算保持线性复杂度，画布重绘通过动画帧合并，标签使用缩放级密度控制。
- 图谱在首次进入页签时加载；过期数据在再次进入页签时刷新；用户可以手动刷新。查看期间不轮询，也不因窗口重新获得焦点而自动重排。
- 文档索引完成或删除成功后只使图谱缓存失效，不在用户查看过程中强制刷新。
- 一期只验收宽度不小于 1,024px 的桌面端。移动端布局、触摸手势和详情面板重排作为后续适配方向。
- LightRAG 离线、返回空图、返回截断图和请求失败使用互不混淆的页面状态，不使用演示或伪造数据兜底。
- Obsidian 仅作为渲染负载控制参照：借鉴 Canvas 类渲染、视口裁剪、标签层级和按需重绘，不照搬其力导向信息架构或私有实现。

## Testing Decisions

- 测试只断言用户可观察行为和稳定数据契约，不断言私有 Canvas 类、内部 React state、颜色哈希实现或具体绘制调用次数。
- 主要测试边界是知识图谱页面的桌面端端到端测试。测试通过可控的全局图谱响应驱动真实页面，验证类别 Top 20 的数量与顺序、没有热门实体入口、类别聚焦、截断提示、搜索定位、节点详情、边关系信息和刷新行为。
- 端到端测试应覆盖多种原始 `entity_type`、空白类别、超过 20 个类别、不连通分量、空图、错误和截断响应。
- Canvas 行为通过可观察结果验证：选择入口后详情和边浮层内容正确、画布像素非空、画布容器尺寸稳定。测试不依赖节点的精确像素坐标。
- 第二个测试边界是前端图谱模型的纯单元测试。它验证类别归一化、统计、稳定排序、未分类与其他分桶、稳定颜色输入、类别聚焦状态、搜索覆盖类别状态、一跳邻接和 5,000 节点布局回归。
- 5,000 节点回归测试应证明模型能够构建完整布局和邻接数据，并且不会为节点生成 DOM；性能测试使用宽松的回归上限，避免依赖特定开发机的精确耗时。
- 刷新测试验证首次进入会加载、缓存失效后重新进入会刷新、手动刷新有效、窗口重新聚焦不会触发意外刷新，并且查看过程中没有定时轮询。
- 搜索测试验证结果只来自 Loaded Graph、每个结果都可定位、截断提示可见，并且搜索选择清除类别聚焦。
- 边交互测试验证全局状态没有全量边标签，选择实体后仅一跳边显示关系类型或关键词及 Relationship Weight，悬停或点击展示描述和来源文件名。
- 节点详情测试验证只展示实体字段，不再渲染完整关联实体列表，不把来源文件名渲染成文档预览链接。
- 现有全局图谱 API 和 LightRAG 归一化测试继续作为后端回归保护。本期不改变后端响应契约，因此不建立新的后端测试边界。
- 现有知识图谱页面端到端测试和图谱模型单元测试是本功能的 prior art，应在其基础上调整断言，而不是建立平行测试框架。

## Out of Scope

- 光伏、储能、充电桩等场站设备的实时拓扑、遥测、告警、调度状态和控制操作。
- 必选中心实体选择器，以及由中心实体重新请求或替换全局图谱的数据流程。
- 热门实体 Top 20 快捷入口。
- 全 workspace 实体类别聚合和完整类别数量。
- 搜索当前 Loaded Graph 之外的实体，以及按搜索结果动态加载或合并新的图谱分量。
- 文档详情跳转、文档预览、原文片段、页码和结构化多来源列表。
- 实体识别置信度、实体创建时间和更新时间。
- 将 Relationship Weight 描述为置信度、概率或准确率。
- 移动端响应式布局、触摸手势和移动端详情交互。
- 替换当前 Canvas 渲染器为 PixiJS、WebGL 或 Obsidian 私有实现。
- 新数据库表、知识图谱持久化副本或新的文档 ID 映射契约。

## Further Notes

- 本 PRD 使用项目领域词汇中的 Knowledge Graph、Loaded Graph、Entity Category、Relationship Edge 和 Relationship Weight。
- 类别和搜索统计口径始终是当前 Loaded Graph。只要全局响应报告截断，页面就必须避免使用“全部”“完整”或“全库统计”等误导性文案。
- 一期支持边点击作为悬停的等价信息入口，但不承诺完整移动端布局。
- 需求已完成逐项确认，没有剩余产品决策。实现应优先复用现有全局图谱契约、Canvas 图谱模型和知识库页面测试入口。
- 相关 Obsidian 调研表明，大型图谱体验依赖数据索引、布局计算、绘制、视口裁剪、标签层级和按需重绘的共同控制；本期采用这些原则，但保持确定性全局布局和 LightRAG 领域语义。
